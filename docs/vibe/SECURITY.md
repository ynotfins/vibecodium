# Security

> Doc class: living · Owner: security-reviewer · Last reviewed: 2026-11-27

## Model

- Secrets are stored only in OS secret storage (Electron `safeStorage`, DPAPI on Windows) or OS environment variables. They are never written to files, logs, prompts, traces or commits.
- All agent shell commands run inside the sandbox (sandbox-runtime) once M6 lands. Auto-approve rules are convenience, not a security boundary.
- Outbound AI requests are decided by the deny-by-default policy core in `src/stable/security/ai-endpoint-policy.mjs`: local model servers are allowed, and Microsoft, GitHub Copilot, telemetry, model-catalog and upstream update hosts are refused until a caller explicitly opts in. See `docs/vibe/design/m1-endpoint-audit.md`. Cloud-metadata hostnames and addresses enumerated in the policy core and the whole IPv4/IPv6 link-local ranges are hard-denied and cannot be enabled by any switch; IPv6 unique-local addresses are not auto-allowed and require an exact host or host+path allow; mDNS `.local`/`.localhost` aliases are re-checked against the same hard-deny set; the whole local-use NAT64 range and the IPv4 metadata addresses embedded in the well-known NAT64 range are hard-denied; option bags with accessors are rejected without invoking them, string arrays are read only through own data descriptors so accessor indices and custom iterators never run, proxy traps can run during structural inspection while any trap failure or revoked proxy fails closed as `invalid-options`, array holes are rejected, and the internal null-prototype option state prevents `Object.prototype` pollution from supplying a switch value in decisions or the policy summary. The live fetch interception is M2/M6 wiring.
- The M2 provider client reads a provider credential once from an explicit options value or the configured environment variable and never returns it in `config`, `describe()`, an error or a serialized client; a credential containing control or bidi characters is rejected before it can become a header value. HTTP failures expose only the status, not the provider response body; streaming and non-streaming responses are bounded by byte, event and tool-call caps, non-streaming bodies must be async iterables read under the cap (there is no unbounded `response.text()` fallback), the request deadline stays armed until the body is consumed, and redirects are refused. A remote provider is unreachable until the caller allows its host/endpoint or opts into external providers, and that opt-in is applied only to endpoints the policy classifies as `external-provider` or `unknown`, scoped by the client to the host the caller configured; Copilot, Copilot-telemetry, GitHub, Microsoft telemetry, model-catalog and update hosts keep their own category switch, and the hard-deny set is never bypassed.
- The M2 fallback chain retries only transient provider failures (timeout, network error, HTTP 408/429/5xx and an empty chat answer); it never falls over for endpoint-policy denial, authentication, malformed request/response, unsupported transport or caller cancellation. Attempt metadata is limited to provider id, label, outcome, error code and status, so a provider response body, prompt, credential or arbitrary error text cannot leak into the final error or `describe()`.
- The M2 task-class router validates the complete policy before use, rejects unknown fields, accessors and model or output-cap overrides, and keeps client objects private. Request data is deep-snapshotted into frozen JSON-safe values before estimation and dispatch, so accessor-backed arrays or objects, sparse arrays, functions, non-finite numbers, cycles and over-deep or oversized input fail closed without invoking a getter and cannot change between estimation and dispatch. It reserves an exact JSON-serialized input byte bound plus the policy output cap against task and UTC-day token budgets before dispatch, so an unaffordable request raises a bounded `budget-exhausted` error without contacting a provider. The task map is capped and fails closed rather than evicting a completed task, and there is no caller-facing task reset, so used tokens cannot be refunded; crossing UTC midnight releases the old reservation and charges actual usage to the current day without subtracting a reservation the new day never held. Routing and budget metadata is limited to the router version, task id, provider id and label, model, task class, output cap, fallback flag, attempt outcome/code/status, UTC day key and integer token counts; prompts, provider response bodies, credentials and client objects never enter that metadata, a router error or `describe()`. For chat requests, the B1 client sends the cap as `max_tokens` for OpenAI Chat and `max_output_tokens` for OpenAI Responses.
- The M2 B6 direct-second-option helper is data-only: it validates the six-class policy maps, requires exactly the `omniroute` and `morph` routes in that order, rejects missing or extra classes, reserved keys, accessors, class-backed maps and invalid models or caps, and returns only frozen route data. It never receives or returns a provider client, credential or endpoint, so its `describe` result and its validation errors cannot leak one; a caller composes it with B1 clients and B3, where B2 supplies only the allowlisted attempt fields described above.
- The M2 B6 Compact pruner is dependency-free and performs no I/O. It reads options, messages and pinned indexes only through own data descriptors and bounds the work as it reads and splits: at most 10,000 messages, 1,000,000 characters per message, 8,000,000 characters and 1,000,000 lines per history, so an oversized history fails closed as `compact-messages` instead of exhausting memory. It rejects accessors, sparse arrays, and revoked or throwing proxies anywhere it reads them, including as the options object or a message element, unknown fields or roles, non-string content and ill-formed Unicode in content, names and tool ids without invoking a getter or echoing the rejected value, and supports histories with string content and optional tool message ids, rejecting `tool_calls` so a tool call and its result cannot be separated. Message names and tool-call ids with control, format or bidi characters are rejected. It returns frozen messages and stats, keeps no client, credential, environment variable or input object, and its error metadata is limited to a fixed name, a code, an optional fixed `scope` label and integer token counts; a custom tokenizer must return 0 only for empty text and must otherwise match or exceed the D4 UTF-8 byte floor, and it is probed for monotonicity, the count charged for a retained suffix is exactly the count that was compared, so an under-counting tokenizer, a tokenizer that fails a monotonicity probe, or a non-deterministic tokenizer fails closed or stays within the budget instead of reporting more than it checked, and a retained history is never reported above the budget. Every surviving line is a byte-for-byte slice of its source, and pinned overflow fails closed rather than truncating a pinned message.
- The M2 B6 Fast Apply tool receives an already-created B1 client and never reads a credential. It accepts one existing file below a fixed workspace root, rejects absolute, drive, UNC, encoded-separator, traversal, reserved-name, control/bidi, symlink, directory, missing, binary and oversized targets, bounds the assembled request to the B1 per-message cap, and reads the source with `O_NOFOLLOW` where the platform supports it plus a stable device/inode check and strict UTF-8 (Windows relies on the path and identity checks because `O_NOFOLLOW` is unavailable). The provider answer is bounded to 2 MiB and must be well-formed text; a result identical to the source is not written. A changed result goes to a unique `0600` temporary file beside the target after a byte-for-byte re-read of the original, and is renamed into place after that final comparison; a narrow check-to-rename race remains. Options, input and the client property are read through own data descriptors, an accessor is rejected without being invoked, and an error carries only a fixed code and an optional integer HTTP status, never the source, edit, instruction, prompt, response body, endpoint or key.
- The M2 B6 WarpGrep tool receives an already-created B1 client and never reads a credential. It runs at most six model turns and executes five read-only tools the model's built-in tools call (literal grep, glob, directory listing, numbered read, finish), with no write capability; no request carries a `tools` array, and it ignores unknown tool arguments while validating every known field, and keeps every path inside a fixed workspace root: a relative path is validated segment by segment and an absolute or drive path is accepted only when its canonical form stays inside the real root, while encoded-separator, traversal, reserved-name, control/bidi and symlink targets are rejected, `.git`, dependency and build folders are skipped by default, and only `node_modules` is re-included with `search_type: 'node_modules'`; the exclusion applies to a directory and to a file whose own name matches, and to every explicit `read`, `finish` or `grep_search` path after `realpath`; credential-shaped names (a best-effort set including `.env*`, `.envrc`, `.netrc`, `.npmrc`, `.pypirc`, `.git-credentials`, `.aws`, `.azure`, `.ssh`, `.docker`, `.kube`, `.gnupg`, `credentials[.json]`, `id_rsa`/`id_dsa`/`id_ecdsa`/`id_ed25519` and their `_sk`/`.pub` forms, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.keystore`, `*.ppk`) are excluded the same way, with the compared name case-folded on case-insensitive filesystems and normalised on Windows so a trailing dot or space cannot alias it, and the `<repo_structure>` turn lists workspace-relative paths only and is capped at 32 KiB, so no absolute local path is sent to the provider. A failing or accessor-backed provider answer fails closed as `invalid-response` without echoing its text; format, bidi, C1 and line/paragraph separator characters in a tool result, the repo-structure listing or the model's reasoning text are replaced with U+FFFD before the next request, and an oversized non-finish tool-call argument above 64 KiB is refused before it is echoed. Files are opened with `O_NOFOLLOW` where the platform supports it plus a realpath and device/inode check, and binary, undecodable and files above 1 MiB are treated as invisible. Grep matches a literal string and globs use a linear segment walk, so a model-supplied pattern or glob cannot cause regular-expression backtracking, and a grep stops after 8 MiB of decoded text. Turn, tool-call, file, line and byte caps bound every loop and result (a glob result is bounded by path count and a 32 KiB output budget), `repo_path` must equal the configured root, options and input are read through own data descriptors so an accessor is rejected without being invoked, and tool and finish arguments arrive as JSON text and are parsed and validated field by field; an error carries only a fixed code and an optional integer HTTP status, never the query, file body, endpoint or key. Workspace file content enters the model context as tool results and can steer which bounded spans are returned, but the tool has no write tool, no network access of its own and never returns the model text, so the loop cannot exfiltrate or write through it; the general untrusted-content quarantine remains the M6 plan below.
- The M2 B6 Router adapter reads the direct-provider key once from an explicit value or the configured environment variable and never returns, serializes or logs it; the router object exposes only `classify` and `describe`, and `describe()` carries no key. It sends exactly one `POST /v1/router/classify` request gated by the M1 deny-by-default endpoint policy before `fetch`, refuses redirects, keeps the deadline armed through the body read and caps the response (declared and streamed) at the configured cap (32 KiB by default, never above 1 MiB); `allowExternalProviders` is scoped to the configured host like the B1 client, so a Copilot, telemetry, GitHub or metadata host keeps its own switch or hard deny. The prompt must be a non-empty, well-formed string without NUL, at most 32,768 characters and 128 KiB of UTF-8, and the options and call-options bags are read through own data descriptors, so a revoked or throwing Proxy, an accessor-backed option or policy, and an unknown or reserved key fail closed; a live Proxy is read only through descriptors, so a get trap never runs, while the `env` seam reads only the named variable once and may invoke an accessor. An unavailable Router degrades to the caller's default tier with one fixed code (`timeout`, `network-error`, `http-status`, `invalid-response` or `response-too-large`) and an integer HTTP status, while invalid options/input, a missing or invalid key, endpoint-policy denial and caller cancellation throw; the prompt, answer body and credential never enter a result, an error or `describe()`, and the only endpoint text anywhere is the redacted `endpoint` property on the shared M1 `AIEndpointPolicyError`, which carries no credential, query or fragment because the base URL forbids them. The classify call is billed per request, so its cost belongs in the B3 budget model, and the prompt is covered by the same provider trust boundary as every other AI request.
- The M2 provider setup service keeps provider definitions in a non-secret settings file that records only the ids of providers with a stored key, rejects a definition containing `secret`, `apiKey`, `api_key`, `token` or `password` on load and on add, and writes the file atomically with a 0600 mode. Keys live in the Windows Credential Manager: a fixed PowerShell P/Invoke script receives the base64 value on stdin, so it never appears in argv, the environment, a file or a log, and the child is the absolute system `powershell.exe`, not a bare name a workspace could shadow through the current directory or PATH; a Win32 failure is reported only as a numeric status and an unavailable host as `secret-store-unavailable`. The panel never renders a key, a setup method never returns one, `createClient()` constructs the B1 client internally, and a panel message is refused above 64 KiB. The real Credential Manager round-trip is environment-limited in the agent sandbox, where the restricted token returns ERROR_NO_SUCH_LOGON_SESSION; the adapter protocol, failure mapping and script parse are covered by tests.
- The M3 local runtime supervisor starts a caller-supplied `llama-server` as a direct child with `shell: false`, binds it to loopback `[127.0.0.1]` and passes an exact server argument list (`--model`, `--host`, `--port`, plus bounded context/thread/GPU-layer flags) after an optional validated caller prefix that may not set the host or port. It never passes the full process environment: only `SystemRoot`, `TEMP` and `TMP` are copied on Windows (`TMPDIR`, `LANG`, `LC_ALL` elsewhere), `PATH` is pinned empty because Windows would otherwise synthesise a system/user search path, and caller overrides may not set `NODE_OPTIONS`, `NODE_PATH`, `LD_PRELOAD`, `LD_LIBRARY_PATH`, `LD_AUDIT`, `DYLD_INSERT_LIBRARIES`, `DYLD_LIBRARY_PATH`, `DYLD_FRAMEWORK_PATH`, the `DYLD_*` fallback paths, `SystemRoot`, `GGML_BACKEND_PATH` or any `LLAMA_ARG_*` name; the comparison is case-insensitive, so a differently cased name cannot slip through. Node still adds a few OS identity variables (`USERNAME`, `USERPROFILE`, `WINDIR` and similar) to a Windows child; no arbitrary parent variable, provider key or caller-selected name outside the validated override list reaches it. Provider keys and loader-hijack names are therefore not inherited from the parent, and explicit caller overrides are trusted only for ordinary names. Caller prefix arguments may not set the bind host or port and may not enable a shared port, the agent loop (`--agent`, `-ag`, `--ui-agent`), the server-side tools (`--tools`) or MCP tools/proxies (`--mcp-*`, `--ui-mcp-proxy`). The child's working directory is the executable directory, not the parent's current directory. Executable and model paths are resolved with `realpathSync.native` and must equal their resolved form, so a symlink or junction anywhere in the path is rejected; empty, missing, relative, drive-relative, UNC, control/bidi and Win32 trailing-dot/space paths fail closed; the executable must be a `.exe` on Windows, the model a `.gguf`, and a POSIX executable must carry an execute bit. Options, argument arrays, environment and the exported argument builder are read through own data descriptors once, so accessors are not invoked, and validation errors never echo the rejected value. Readiness is gated on redirect-refusing `/health` polling; each request has a 2-second deadline, and the child is killed when the startup deadline expires before the start fails. `health()` reports not-ready outside the running state. An optional `restart` policy is validated through own data descriptors (a revoked Proxy, a Proxy whose enumeration or descriptor trap throws, an accessor, a reserved key, a missing or out-of-range field, or a `maxDelayMs` below `baseDelayMs` fails closed without a child) and only restarts the direct child the supervisor itself spawned, on the same loopback port, with a bounded exponential back-off and budget; it cannot change the executable, model, arguments or environment, its timers are unref'd, a stop cancels any pending restart, and the budget ends in `failed`/`restarts-exhausted` rather than an unbounded crash loop. Residual risks: the supervisor trusts the caller-supplied executable to live in a directory an attacker cannot replace (the later bundled binary will be installer-owned); readiness accepts a 200 from any listener on the chosen port, which matters most when the caller supplies a fixed port (an ephemeral port narrows it to a close-to-bind race), so the client-wiring slice must add a port-ownership or per-start authenticated check; upstream `llama-server` defaults to no API key and permissive CORS, and this slice adds neither, so the loopback port is reachable by local processes and web pages until a later slice restricts it; on Windows only the direct child is terminated, so a spawning server would leave descendants, and a parent crash leaves the child running on loopback until it is killed; the retained output tail is bounded in memory and not exposed, but redaction is not implemented; and `commandArgs`/`env` are a trusted caller surface where only the named host/port, shared-port, agent/MCP and loader/system values are refused.
- The M3 model downloader installs weights only when the bytes match the pinned size and SHA-256 in `vibe/models/catalog.json`. A catalog entry must name a 40-character commit revision, a single plain `.gguf` file, a 64-character lowercase digest and an exact byte count, and its URL may not carry credentials, a query string or a fragment, so the ship file cannot smuggle a presigned token; the catalog has no header or token field at all. A download is requested without credentials or caller headers, and the final redirect target must be HTTPS, or plain HTTP on a loopback host only when the pinned URL itself is loopback, with no credentials, query or fragment; the runtime performs the intermediate hops, so no credential is ever sent to them and the digest is the integrity gate. A missing destination is created only after the nearest existing ancestor has been resolved and confirmed to be a real, non-symlink directory; the destination must then be a real, non-symlink directory, and the `.part` name is derived from the catalog entry, never from a response header. Both target files are inspected with `lstat` and refused when they are symlinks or not regular files, so a planted junction cannot redirect the write or the append; a hard link to another file is indistinguishable from a regular file, which remains a residual risk for an attacker who can already write to the model directory. An existing final file is hashed and reported when correct, and is replaced only by verified bytes. Bytes are bounded by the pinned size, a partial file is kept after a cancellation, stall, timeout or dropped body so the next call resumes, and a size or digest mismatch removes the partial file instead of installing it. Free space is checked before the first request when the host exposes `statfsSync`. Errors carry a fixed code and, for `http-status`, one integer status; results and progress events carry only flags, byte counts, the installed path and the pinned digest, never the URL, a response body or a credential. Residual risks: another local process with write access to the model directory could replace the file between the final hash and the rename, and the product will own that directory; the digest is the authenticity record for a pinned revision; and parsing a malicious GGUF after download belongs to the runtime, not this module.
- The M3 sidecar installer installs `llama-server` only when the archive and every extracted file match the pinned size and SHA-256 in `vibe/sidecars.json`. The manifest is read through own data descriptors, so an accessor is rejected without being invoked, a Proxy is read without running a get trap, and a prototype cannot supply a key; a duplicate id or path, an unknown or reserved key, a non-permissive license, a non-HTTPS (or non-loopback HTTP) URL, a URL with credentials, query or fragment, a bad platform key, a traversal/absolute/backslash/reserved-device/trailing-dot path and an executable outside the file list all fail closed. The archive is requested without a credential or caller header, the final response URL must be HTTPS (or loopback HTTP only when the pinned URL was loopback), with no userinfo or fragment (a query is allowed on the final redirect target because GitHub's release CDN signs it), a literal loopback, private, link-local, metadata or `localhost` final host is refused when the pin was not loopback, including the IPv6 forms that embed an internal IPv4 address (IPv4-compatible, IPv4-mapped/SIIT, both NAT64 prefixes and 6to4) and the `fe80::/10`, `fc00::/7` and `ff00::/8` ranges; a DNS name is not resolved, so a name that resolves internally remains a residual, the pinned SHA-256 is the integrity gate, and intermediate hops are followed by the runtime and see only transport headers, a declared length must equal the pin, and the stream is counted and hashed against it. Only names that exactly match an allowlisted file are extracted from the ZIP, every archive entry name is checked as a safe relative path, symbolic-link attributes, duplicate names, encrypted entries, an allowlisted entry with an unsupported method, ZIP64, multi-disk archives, missing entries and oversized entries are refused, a nested parent directory is re-checked through `realpath` and must stay inside the target directory, the archive is read once and that same buffer is hashed and parsed, and each inflated file is bounded, size-checked and hashed again. All files are verified before the first write; each is written to a unique temporary file and renamed, so the install is per file and not transactional (a failed rename leaves the earlier verified files in place), then re-inspected and re-hashed, and after a fresh install the executable is passed through the supervisor's validator; the skip path trusts the offline inspection without calling it again. The installer never executes the binary, the archive is removed, and an error, result, progress event or summary carries only a fixed code and integer status/byte counts, never the URL, an archive body, a credential or the injected error. The pinned target is CPU-only: no CUDA, Vulkan or OpenCL backend ships, so a GPU-layer or GPU-acceleration plan is inert until a GPU target is pinned, and the first-run plan must reconcile its acceleration verdict with the bundled backend. The pin records both licenses (`mit` and `apache-2.0-with-llvm-exception`), so the checked third-party notice carries llama.cpp's MIT text and the bundled `libomp.dll` Intel OpenMP text. The manifest is not signed yet, the pinned build is a nightly because the stable llama.cpp tags publish no binary assets, and the Microsoft VC++ 2015-2022 x64 runtime is a separate, currently unpinned dependency; signing, packaging, placing the generated notice in the packaged application and the runtime belong to later M3/M12 work. The `busy` guard is process-local, `publishedAt` and `source` are not enforced against the URL at load, the manifest is unsigned, and `targetDir` is a trusted caller surface that `verifySidecarInstall` creates, so an authenticated manifest and an installer-owned application-data directory are gates before the installer is enabled by default or the binary is bundled.
- The M3 hardware probe runs one fixed read-only `Win32_VideoController` CIM query and passes no caller input to it. The child is the absolute system `powershell.exe` with `-NoLogo -NoProfile -NonInteractive -EncodedCommand`, no shell, no stdin, `windowsHide`, a bounded timeout and a 64 KiB output cap, and its environment is built from only an allowlist (`SystemRoot`, `windir`, `TEMP`, `TMP` and an empty `PATH`); Windows still exposes a small fixed set of OS identity and shell-path variables to the child, but no arbitrary parent variable, provider key or caller-selected value reaches it, so a workspace cannot shadow the executable; a relative `SystemRoot` is ignored rather than trusted. The probe also enforces its own deadline around the runner. The answer is parsed under a byte cap and every field is bounded before it reaches a plan: each adapter line must be canonical base64 with a valid UTF-8 payload, a name of at most 200 characters without control or bidi characters, and a decimal size of at most 15 digits; a malformed, oversized or hostile line, more than eight adapters, an interior empty line or a non-zero exit discards the whole GPU list with a bounded notice, and no child output is surfaced or echoed. A non-Windows platform never shells out; a failed or unavailable GPU query leaves no adapter to offload to, so the plan uses the CPU (or unified memory on Apple silicon) rather than guessing an offload target. The OS-provided CPU name is stripped of control and bidi characters, whitespace-collapsed and length-bounded before it enters the descriptor. `recommendRuntime` reads the hardware descriptor and the model list only through own data descriptors and rejects an object Proxy before any trap can run; the GPU and model arrays are read element by element, so an accessor element, a hole or a throwing trap fails closed while a Proxy array that answers with data properties is accepted as supplied, and unknown or reserved keys, duplicate model ids and accessor-backed values are rejected without invoking a getter. It requires the chat and embedding roles and returns frozen data that never aliases the input; its result only proposes numbers for `llama-server` flags, which the supervisor validates independently. Residual risks: `Win32_VideoController.AdapterRAM` is a UInt32 capped near 4 GiB, so a large card's exact size is unknown and the plan treats the capped value as "at least 4 GiB"; adapter classification is name-based, so a mislabelled device could be classified as discrete and offload slowly, which cannot corrupt data; the probe does not query NVML/ADL, eGPUs or hybrid-graphics routing; an array Proxy can run its own traps while its descriptors are read, though it cannot make the plan alias its values; and the optional `exec` option is a trusted caller/test seam, so a caller that supplies one runs its own child, like the supervisor's caller-supplied binary.
- The M3 first-run wizard never spawns a process and reads no model file; the only network effects it adds beyond the existing downloader are the optional Ollama detection, delegated to the reviewed loopback probe below, and the optional pinned sidecar install, delegated to the reviewed installer below. It validates the catalog, then probes, verifies and downloads through injected functions whose product defaults are the reviewed `probeHardware`, `verifyInstalledModel`, `downloadModel`, `installSidecar` and `verifySidecarInstall`; options, the probe result, install options, the sidecar bag, the discovery answer and the installer result are read through own data descriptors, so a Proxy, accessor, unknown or reserved key, traversal destination, invalid executable path, malformed manifest, unknown sidecar id, unsupported platform or a non-function effect fails closed without invoking a getter. The sidecar `targetDir` is host-owned and must be an absolute local path (the default is `<destinationDir>/runtime`), never a webview value; an already installed runtime is adopted on refresh through the offline verifier, and a failed or hostile verifier is advisory and never fails the refresh. The view is frozen; the panel accepts only a public error code matching `^[a-z0-9][a-z0-9-]{0,63}$` and otherwise shows a fixed message, so an injected error body, file path or credential is never echoed, and progress carries only catalog ids, byte counts and a fraction. A webview message must be a plain object (not a Proxy or an array, with `Object.prototype` or a null prototype) with exactly one own enumerable data `type` property; a Proxy or revoked Proxy, an array, an unknown key, an accessor, a non-object and a non-string `type` are rejected as `invalid-message`, and `type` is capped at 64 KiB of UTF-8. The panel sets one fresh 24-character base64 nonce in `default-src 'none'; style-src 'nonce-…'; script-src 'nonce-…'; base-uri 'none'; form-action 'none'` and on the matching `<style>` and `<script>` tags, and the fallback page carries a valid nonce too. The panel only assembles the start plan and never starts the process itself; the start action calls the injected installer at most once, forwards bounded byte progress, and validates the returned executable with the supervisor's own path check before publishing it, so a non-verified, accessor-backed, Proxy or missing result fails as a bounded `runtime-install-failed` with no path echo. The start action still never executes the binary. Its Ollama section is read-only until the user selects the daemon: `checkOllama()` shares at most one in-flight call to the injected discovery (the reviewed loopback probe by default, policy-gated before the request), is single-flight, never changes the plan and never adopts the daemon; the summary is rebuilt through own data descriptors and exposes provider overrides only after `toOllamaProviderOptions` re-validates the whole answer, so a forged, stale, remote, embedding-only or wrong-base answer yields none, and a thrown effect, Proxy, accessor, unknown reason or oversized field list degrades to a bounded `check-failed`/`invalid-result` value with no URL, model text, body, error message or credential echoed. `useOllama()` is an explicit, bounded selection that succeeds only after a check found a daemon whose summary still carries validated provider overrides and only while no download is in flight (`not-checked`, `ollama-unavailable`, `not-ready`, `busy` and `disposed` otherwise); it changes only the wizard's own start plan, phase and `view().source`, returns `ollama-selected` from `install()` instead of downloading, exposes a daemon start plan with just the validated loopback base URL, chat model and optional embedding model, and never starts, installs or updates the daemon or writes provider config. `usePinned()` restores the pinned phase, and a re-check that loses the daemon releases the selection. The panel calls the check once on open and forwards bounded `ollama`, `use-ollama` and `use-pinned` messages, answering `unknown-message` when a wizard lacks the optional control methods. The restart policy is validated data, not behaviour: the wizard reads a caller-supplied policy through own data descriptors with the supervisor's exported validator (an accessor that is never invoked, a revoked or trap-throwing Proxy, a reserved or unknown key, a non-integer or out-of-range value or a cap below the base delay fails closed before the probe), falls back to the frozen conservative default, and carries exactly the six supervisor fields in `runtimeOptions()`; a malformed, out-of-range or accessor-backed policy is omitted from the panel instead of throwing, and a selected daemon yields the daemon start plan rather than supervisor options. The panel and wizard still spawn nothing. The start action now installs the pinned binary, but copying it into the packaged application, signing the manifest and the real extension-host smoke remain later M3/M6/M12 work.
- The M3 Ollama discovery makes at most one read-only loopback request (none when the M1 policy denies it) and never starts, installs or updates the daemon. The host is fixed to the loopback address and the path to `/api/tags`; the port is an integer in 1024-65535; no credential, cookie or caller header is sent; the endpoint is evaluated by the M1 policy core before the request; redirects are refused; a present content type must be `application/json` or `application/json;...` (case-insensitive), and a missing one still has to parse as JSON; one deadline covers the request and the body; the body is read under a default 256 KiB cap that a caller can raise to at most 4 MiB (a body-less injected response is materialized with `text()` and checked afterwards, and the product fetch path always reads a stream), with a 256-model cap; and the answer is parsed only through own data descriptors, so an accessor is rejected without being invoked. Model names must match the model-name class of the provider preset, metadata is bounded, control, format and bidi characters are rejected, and the returned view is frozen and never retains the `modified_at`, `digest` or response text of the daemon. The M1 policy is consulted through an `evaluate` function that defaults to the policy core; a denial, a missing decision or a throwing evaluator returns `policy-denied` without a request, and a caller-supplied evaluator is a trusted seam in the same class as `fetch`. `toOllamaProviderOptions` re-checks the result version, the loopback base URL and the default chat and embedding models against the returned list with the correct remote and embedding flags, so a forged or stale result cannot point a default at a cloud or embedding-only model. Failures are values with one bounded notice (`unreachable`, `timeout`, `http-error`, `invalid-response`, `policy-denied`), so no URL, body or error text is echoed. Cloud/remote models (`remote_model`, `remote_host` or a `:cloud` tag) are listed but never selected. The bounded metadata (`family`, `families`, `parameter_size`, `quantization_level`) is untrusted display text and must be rendered as text or tagged as untrusted before it reaches HTML or an agent prompt. Residual risks: any loopback service that answers `/api/tags` with a valid shape is treated as Ollama, though the only effect is the names and base URL offered to that same endpoint with no secret and no write; the embedding flag is a family/name heuristic; the B1 client sends `tool_choice: auto` with tools while the Ollama compatibility table does not list it, which a live smoke must settle; and the daemon can change between discovery and use.
- Planned for M6: untrusted content (web pages, MCP tool output, files from the internet) is tagged and summarized by a tool-less model before a privileged agent acts on it.
- Shipped artifacts contain only permissive licenses; see `ARCHITECTURE.md` principle 8.
- The third-party notice is generated, not hand-written, and cannot pass with a gap. `vibe/notices.json` pins each license text under `vibe/licenses/` by SHA-256 and an absolute HTTPS URL without credentials, and the ledger is read through own data descriptors, so an accessor is rejected without being invoked and a trap-throwing or revoked Proxy, a reserved key, a duplicate identifier, a traversing text path and a malformed digest all fail closed. `src/stable/runtime/third-party-notices.mjs` projects every pinned sidecar and model into a component and refuses to render when a component's license has no text, when a text no longer matches its digest, or when the component projection is malformed; the notice carries no absolute path, the license bodies are emitted verbatim and no network request is made. `node vibe/tools/notices.mjs` is the only writer of `docs/vibe/legal/THIRD-PARTY-NOTICES.md`, `verify` runs it in check mode, and a missing or stale document fails the build. Placing that document inside the installer or beside the installed files is M12 packaging work, so today it is a repository artifact only.
- Bundled binaries are pinned by SHA-256 and signed once a signing route is chosen.
