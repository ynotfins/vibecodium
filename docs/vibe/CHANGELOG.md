## [Unreleased]

### Added

- The local runtime can now discover an existing local Ollama daemon without typing a URL or a model name. `src/stable/runtime/ollama.mjs` makes at most one `GET /api/tags` request to the loopback host at a validated port (11434 by default), with a deadline, a 256 KiB response cap (raiseable to 4 MiB) and no credentials, evaluates the endpoint through the M1 policy before the request (a denial returns `policy-denied` with no request), and projects the answer through own data descriptors: a name-sorted, bounded model list that treats null metadata as absent, marks embedding and cloud/remote models, picks the largest local chat model and the largest local embedding model, and returns bounded notices instead of throwing or echoing the body. `toOllamaProviderOptions` returns exactly the `baseUrl` and `model` overrides the B1 `ollama` preset takes and refuses an unavailable result, an unknown, remote or embedding-only model, or a forged or stale default. The acceptance test drives the preset through the discovered base URL for chat, streaming, tool calls and embeddings against a loopback mock server. Nothing calls the discovery from the UI yet; wiring it into the first-run wizard and the provider setup panel, a live smoke, the llama.cpp binary bundle, copying the catalog into the packaged application and restart/back-off remain M3 work.
- The first-run setup now composes hardware detection, the pinned catalog and the downloader into one flow. `src/stable/runtime/first-run.mjs` projects the catalog's chat and embedding entries to the four fields the recommendation accepts, probes the machine once, reports which pinned files are already installed, and refuses an insufficient machine rather than downloading weights that cannot run. It downloads only the missing files chat first, forwards progress, verifies each file before marking it installed, keeps a resumable partial after an abort or a failed transfer, and a retry skips models that already verified. The start plan reports `runtime-not-bundled` until the llama.cpp binary is bundled and otherwise carries the chat and embedding model paths plus the context, thread and GPU-layer numbers the supervisor consumes. The setup panel (`vibecodium.firstRun.open`) renders the verdict, steps, models, notices and progress and drives the check, download and start actions through bounded, escaped messages. The panel and wizard are not yet connected by the workbench. The llama.cpp binary bundle, copying the catalog into the packaged application and restart/back-off remain M3 work.
- First-run hardware detection now reports what the machine can run before anything is downloaded. `probeHardware` collects platform, architecture, CPU model, logical core count, total and free memory and, on Windows, the display adapters from one fixed read-only PowerShell `Win32_VideoController` query whose child is the absolute system `powershell.exe`, bounded by a timeout and an output cap. Each adapter is returned with its decoded name, vendor, kind and reported memory (the script sends the name base64-encoded); a malformed, oversized, hostile or failed answer degrades to no GPUs with a bounded notice and never surfaces child output, and other platforms report that the GPU probe is unavailable instead of shelling out. `recommendRuntime` maps the facts and the pinned catalog to a frozen start plan: verdict, acceleration, chat and embedding model ids, context size, thread count, GPU layers, estimated chat and embedding memory and notice codes. A discrete GPU that can hold the smallest chat model (a 4 GiB card is enough for the pinned 1.5B chat model) offloads every layer, the WMI 4095 MiB `AdapterRAM` cap is marked `vram-capped` rather than mistaken for a small card, Apple silicon uses unified memory, an integrated or software GPU and a machine without a GPU stay on the CPU, RAM below 8 GiB is `insufficient` and below 16 GiB (or any CPU-only plan) is `tight`, and a GPU that cannot hold the smallest chat model falls back to RAM. The llama.cpp binary bundle and restart/back-off remain M3 work.
- The gateway now provides a bounded `codebase_search` tool that answers a natural-language question about the workspace through the WarpGrep model. A short read-only loop of at most six turns lets the model search literal text and read files, then finish with the answering paths and line ranges; the tool returns those spans with bounded content and token usage. It never writes, stays inside the caller's workspace, skips `.git`, dependency and build folders and credential-shaped files such as `.env` or `*.pem` by default, lists the workspace with relative paths only, refuses escaping, symlinked, binary and oversized files, caps every turn, tool call and result, and reports no query, file body, endpoint or credential in an error. The agent-host wiring remains M6 work; a live provider smoke test remains M2 work.
- Local model provisioning now has a pinned catalog and a resumable downloader. `vibe/models/catalog.json` pins two Apache-2.0 GGUF files (Qwen2.5-Coder 1.5B Instruct `q4_k_m` and Qwen3-Embedding 0.6B `q8_0`) by commit revision, SHA-256 and exact byte size, and the catalog refuses a branch revision, a non-GGUF or nested file name, a disallowed license, a plain-http non-loopback URL and a URL with credentials, query or fragment. `downloadModel` streams the weights into a partial file, resumes an interrupted transfer with a `Range` request, follows a redirect only to another HTTPS URL, or loopback HTTP when the pinned URL is loopback, keeps a partial file after a cancellation, stall, timeout or dropped body, checks free space before the first request, and installs a file only when its size and digest match the pin; a mismatch removes the partial file and never leaves unverified bytes under the final name. `verifyInstalledModel` reports whether a model is already installed without touching the network. The `llama-server` binary and copying the catalog into the packaged application remain M3 work.
- The local runtime now has a supervisor for a caller-supplied llama.cpp `llama-server`. It starts a direct child with `shell: false` on `[127.0.0.1]`, passes the server flags exactly `--model`, `--host` and `--port` plus optional bounded context, thread and GPU-layer flags, resolves `start()` only after `/health` returns 200 and reports the port, base URL and pid. `stop()` is idempotent and escalates from `SIGTERM` to `SIGKILL`; never-ready and unhealthy children are stopped, and an early-exit child fails closed as `server-exited`. The executable and model must be real files with no symlink or junction in the path, the child runs in the executable directory with an allowlisted environment and an empty `PATH` unless the caller supplies one, loader/system and `LLAMA_ARG_*` environment names are refused case-insensitively, prefix arguments cannot enable a shared port or the agent/MCP tools, and the controller, its argument list and its status are frozen. The B1 `llama-cpp` preset serves chat, streaming, tool calls and embeddings from the fixture spawned by the supervisor in the acceptance test; connecting the preset to a supervised server in the product remains later M3/M6 work. Bundling or downloading the llama.cpp binary remains M3 work.
- The gateway now provides a bounded `edit_file` tool that merges a lazy edit into an existing workspace file through Fast Apply. The tool sends one `<instruction>`, `<code>` and `<update>` turn to `morph-v3-fast` through the provider client, then writes the merged result atomically. It stays inside the caller's workspace, refuses absolute, traversal, UNC, encoded, symlink, missing, binary and oversized targets, re-checks the original immediately before the rename (a narrow check-to-rename race remains), and reports no source, prompt, credential or response body. The agent-host wiring remains M6 work.
- The context engine now has a standalone history compactor that reduces a chat history to a token budget without rewriting it; the in-IDE history path is not yet surfaced. `src/stable/context-engine/compact.mjs` keeps every `system` message, explicitly pinned messages and the newest messages, drops whole older messages and only the oldest whole lines of one boundary message, and guarantees that every surviving line is byte-identical to its source; pinned content that alone exceeds the budget fails closed instead of silently truncating, and histories that carry tool calls are rejected until tool-call pairing can be dropped as a whole. A caller tokenizer is supported but must match or exceed the D4 byte estimate and be monotone, and the reported estimate never exceeds the budget. Oversized histories, under-counting tokenizers and a tokenizer that fails a monotonicity probe fail closed; message, character and line caps bound the input as it is read and split.
- Model work now has a deterministic direct second option. A dependency-free helper builds the full six-class B3 policy with OmniRoute first and the direct provider second, using an explicit model and output cap for each class in place of silent defaults. With OmniRoute stopped, chat and embeddings still complete on the direct provider in the same turn; the answer reports the serving provider and bounded attempt metadata that contains no response body, prompt, endpoint or credential. A missing, extra, malformed, accessor-backed or reserved-key map fails closed without invoking a getter or echoing a value. WarpGrep, Router, hosted models, the approval-gated abliterated model and live smoke tests remain B6 work; Fast Apply agent-host wiring remains M6.
- Model providers can now be added and switched from a provider setup panel without editing a file. The panel lists the catalog, marks the active provider, shows whether a key is stored, offers environment-variable names (each preset configured key variable plus credential-shaped names set in the process) as the key picker (never their values), and imports the selected variable's value into the Windows Credential Manager. Provider definitions are stored in a non-secret settings file that records only which providers have a stored key; a definition containing a secret field is rejected, and no key is ever rendered in the panel, returned by the setup API, written to a file or included in an error. The real Credential Manager round-trip is environment-limited in the agent sandbox, where a restricted token returns ERROR_NO_SUCH_LOGON_SESSION; the adapter protocol, failure mapping and PowerShell script parse are covered by tests. Bifrost supervision, the B6 direct-provider features and live provider smoke tests remain M2 work.
- Model work can now be routed by task class. A validated policy table selects the provider, model and output cap for plan, code-edit, quick-edit, review, summarize and embed, composes the ordered provider fallback for each class, reports the selected and serving provider, and sends the chat output cap on both OpenAI Chat and OpenAI Responses requests. Per-task and UTC-day token budgets reserve an exact JSON-serialized input bound plus the cap before dispatch and stop a request with a bounded `budget-exhausted` error, without calling a provider, when either budget cannot cover it; request data is snapshotted, the task map fails closed at its cap, and used tokens cannot be reset by the caller. Provider response bodies, prompts, credentials and client objects never enter the budget or routing metadata.
- Provider requests can now use an ordered fallback chain. A timeout, network error, HTTP 408/429/5xx or empty answer moves to the next configured provider in the same turn, including streaming text and tool calls, while policy denials, authentication problems, invalid requests and cancellation still stop immediately. Successful answers report which provider served them, and an exhausted chain fails with bounded attempt summaries that contain no response body, prompt or credential. Bifrost wiring remains future M2 work.
- The M2 B1 provider layer now ships a dependency-free, frozen catalog for OmniRoute, Morph, kie.ai Responses, DeepInfra, Abliteration, OpenRouter, Requesty, any OpenAI-compatible endpoint, llama.cpp and Ollama, plus a settings-JSON path that can add a provider or override a built-in without editing source. A request client implements both OpenAI Chat Completions and OpenAI Responses, assembles streaming text and streamed tool arguments under event/byte caps, exposes embeddings only where a preset advertises them, reads the credential once and never returns, serializes or logs it, suppresses provider response bodies from HTTP errors, and sends every request through the M1 deny-by-default endpoint policy; local model servers stay allowed by default, while a remote preset needs an exact host/endpoint allow or the external-provider opt-in, which the client scopes to the configured host. Every request refuses redirects, keeps the deadline armed until the body is consumed, requires an async-iterable body under the byte cap, and rejects control or bidi characters in a credential; the external-provider opt-in applies only to endpoints the policy classifies as external-provider or unknown, so it cannot reach Copilot, Copilot-telemetry, GitHub or metadata hosts. Bifrost supervision and live smoke tests remain M2/M3 work.
- The M1 Microsoft endpoint audit now ships as `docs/vibe/design/m1-endpoint-audit.md` plus a dependency-free, deny-by-default decision core in `src/stable/security/ai-endpoint-policy.mjs`. The audit covers the Microsoft, GitHub Copilot CAPI, Copilot telemetry, 1DS telemetry, Azure ML model-catalog and upstream VS Code update hosts reachable from the pinned `1.143.1` AI services in the scanned directories, with the source file and disposition for each. `evaluateAIEndpointRequest()` allows loopback, private-LAN and on-device model servers by default and denies every remote family until a caller opts in by category, exact host or host+path; credential URLs, non-HTTP schemes, control/bidi characters, punycode hosts and invalid options fail closed; option bags with accessors are rejected without invoking them, string arrays are read only through own data descriptors so accessor indices and custom iterators never run, proxy traps can run during structural inspection while any trap failure or revoked proxy fails closed as `invalid-options`, array holes also fail closed, and prototype pollution cannot supply a switch value in decisions or policy summaries; `redactAIEndpoint()` keeps logs free of userinfo, query and fragment. IPv4/IPv6 link-local ranges and the enumerated cloud-metadata hostnames and addresses are hard-denied before any opt-in is considered; mDNS `.local`/`.localhost` aliases are re-checked against the same hard-deny set, the whole local-use NAT64 range and the IPv4 metadata addresses embedded in the well-known NAT64 range are hard-denied, and IPv6 unique-local addresses need an exact host or host+path allow. Live interception stays M2 (Bifrost) and M6 (agent host) work.
- The native VS Code AI surfaces now open on a clean profile without a user-installed GitHub Copilot extension or a GitHub sign-in. `prepare_vscode.sh` applies a dependency-free product transform after merging `product.json`: it replaces `defaultChatAgent` with a Vibecodium descriptor owned by the built-in `vibecodium.vibecodium-ai` extension, removes every Copilot-branded entry from the owned sections (default chat agent, trusted auth, built-in/auto-update, recommendation including language, tool and chat-session tips, session, API-proposal, gallery-property, forced-version, auth-inheritance, remote-default-extensions and configuration-policy lists) and leaves only the gallery telemetry SKU names and the workspace-trust copy alone; the build also drops the bundled `extensions/copilot` folder, and points every runtime endpoint at the reserved `https://vibecodium.invalid` host. The built-in extension defaults `chat.disableAIFeatures`, `chat.titleBar.signIn.enabled` and `chat.welcomePage.signIn.enabled` so chat stays on and sign-in prompts stay off, including on hosts that predate the welcome-page setting. The branding patch drops the ` Copilot` agent-name suffix and the Copilot setup wording. A real extension host (the installed VS Code host; a rebuilt-app smoke remains M12) proves chat, inline chat, the Agents window, sessions and checkpoint restore are available on a throwaway profile (its extensions directory starts empty, so this proves the surfaces and classifier wiring, not the owner's normal profile) with no user-installed Copilot extension and no GitHub session; the test disables the stock host's built-ins by exact id, the runner asserts an empty user-installed list, a stock host may still list or load its own bundled Copilot Chat, and a planted probe proves the classifier detects one when present. Model and provider wiring remains M2.
- The standalone docs-mcp server now gives agents bounded, read-only access to explicitly configured Markdown documentation roots over MCP stdio. Its `docs_list`, `docs_search` and `docs_read` tools keep all paths project-relative, label every result `untrusted-documentation-content`, neutralise control and bidi characters, cap documents, bytes, snippets, search results and reads, and never fetch from the network. The CLI is `node src/stable/docs-mcp/server.mjs --root <id>=<absolute-directory>`; Bifrost and IDE wiring remain later milestones.

Every node and edge carries `sourceTrust: 'untrusted-repository-content'`; identifiers, names, project-relative paths, routes, environment-variable names, ports, tables, MCP tools and container images are copied, while source text, environment values and request URLs are not. The graph engine remains the only edge authority. The M5 license and integration decision is recorded in `docs/vibe/spikes/understand-anything.md`.

- The built-in `vibecodium-ai` extension now provides the D3 memory review panel core. `MemoryReviewModel` validates every field of a `MemoryStore.review()` page, bounds values to a 2,000-character preview, keeps the queue counts and page state, and fails closed on unknown fields, duplicate ids, cross-scope items, forged trust markers, malformed revisions and oversized pages. The renderer uses a fresh CSP nonce per document, escapes all memory text, and renders keyboard-accessible scope, status, paging and approve/reject/forget controls. The controller registers `vibecodium.memory.open` and `vibecodium.memory.setStore`, reloads after every action, refuses an action whose id or revision is not the exact fact on screen, and never trusts a page item's scope. - The built-in `vibecodium-ai` extension now provides the first cross-project graph panel: an editor-area webview with a CSP nonce, theme-aware keyboard-accessible nodes, workspace -> project -> module -> symbol drilling, breadcrumbs, bounded views, HTML escaping, and click-through to the source at the selected symbol or route. The panel consumes the standalone C3 graph through a small controller, accepts graph data plus a `projectRoots` sidecar through `vibecodium.graph.setData`, and registers `vibecodium.graph.open`. The panel tests cover the fixture graph, all four zoom levels, route rendering and route-definition edges, HTML escaping, click-through and a 10,000-symbol bound. The full VS Code extension build and an in-IDE screenshot remain M6/M12 integration work; the extension host contract is unit-tested with a fake `vscode` API.

- The standalone index now has a cross-project graph edge layer. `buildCrossProjectGraph(registry)` reads the current indexes of the registered projects plus bounded, contained reads of source, `package.json`, Dockerfile and compose files, and emits project, module, symbol, route, package, env, port, database-table, MCP-tool and container nodes with project-module, route-definition, import, package-dependency, env-use, exposes-port, database-table-use, mcp-tool, container-image and `http-route-caller` edges. Route-to-caller matching links a client symbol in one repository to a route definition in another for the C3 acceptance check, with GET/POST kept distinct, caller template URLs tagged `template`, templated route definitions normalized to `:param`, client receivers such as `httpClient` distinguished from server receivers such as `router`, comments and string-only calls ignored, and absolute origins, query strings and base-URL variables stripped. The graph stores only identifiers, project-relative file paths, normalized route patterns, environment-variable names, ports, table names, tool names and image names; source values, environment values and request URLs are not retained. Import edges keep only a resolved project-relative target or a package name, stripping query strings and dropping URL or colon-bearing specifiers. Nodes, edges, caller answers and the snapshot carry `sourceTrust: 'untrusted-repository-content'`. HTTP caller extraction is capped at 1,000 per file and 5,000 per graph, and route matching uses a method-keyed trie instead of scanning every caller against every route. Route indexing is also bounded to 64 segments per route and 200,000 trie nodes; HTTP caller candidates are capped at 20,000 per file and route ranges are merged so exclusion is a binary search; the import/export scan is length-bounded. The public `CrossProjectGraph` constructor validates a persisted snapshot field-by-field, rejecting unknown fields, duplicate ids and missing references, and forces `sourceTrust` on nodes and edges. Every trie node, including parameter nodes, counts against the 200,000-node budget; each read stops at 1 MB + 1 byte and re-checks the size; persisted node and edge ids are restricted to a safe identifier alphabet and edge ids are deduplicated; a saturated route-range table disables caller inference for that file rather than risking false matches. Every source read is project-relative, rejects traversal and absolute keys, follows no symlinks, revalidates device/inode and containment, and is bounded per file, per project and in total; malformed registries, index snapshots and route queries fail closed with `CrossProjectGraphError`. This is the standalone C3 layer only: the graph panel (C4), IDE binding, persisted graph tables and semantic/LSP edge extraction remain later work. `node --test tests/vibe/cross-project-graph.test.mjs` builds two fixture repositories and asserts the route-to-caller edge plus the other C3 families, client.get/client.post callers, template-route normalization, the no-source-values boundary, forged-index rejection and the HTTP caller caps.

- The standalone index can now persist its file embeddings to LanceDB through an optional, caller-injected `@lancedb/lancedb` 0.41.0 driver. `ProjectIndex` takes a `vectorStore`, mirrors changed files with merge-insert, deletes removed files, and exposes `searchVectors(query)`. The store validates the driver, local-only database uri (format and bidi characters rejected), table shape, record hashes, vectors, dimensions, file names and returned hits; it rejects duplicate ids and unreadable row, result and merge-insert builder accessors, bounds cosine distance, chunks large deletes, tags results `untrusted-repository-content`, and takes no dependency of its own, so nothing is downloaded or bundled and `node vibe/tools/verify.mjs` still runs on a bare Node install. `refresh({ full: true })` backfills a new store for an existing index; `load()` keeps using the store that was already populated. The index and the vector store are not one transaction: the index is verified before the store is synced and the store is synced before the index file is written, so a store failure rejects the refresh; a failure after the store sync can leave newer vectors until the next refresh reconciles them.
- The standalone index now has an optional ast-grep structural pattern provider. A caller supplies a trusted local `sg` executable (the ast-grep 0.51.3 CLI contract: `sg run --stdin --lang <lang> --pattern <pattern> --json=stream --color never`); the provider writes the source to stdin, never scans a directory or writes a rule file, runs with shell execution disabled, filters secret-named and loader-hijack environment variables, enforces a timeout plus source, output, match and meta-variable caps, converts ast-grep's zero-based positions to one-based, normalizes its PascalCase language values, and rejects malformed streams, wrong-language matches and prototype-polluting meta names. Exit code 1 is treated as "no matches". Nothing is downloaded or bundled, and `ProjectIndex` does not use this provider yet. Returned match and meta-variable text replaces control, format and bidi characters, the result is tagged `sourceTrust: 'untrusted-source-content'`, the child environment also drops URL, URI and DSN variables plus Node, Electron and Bash loader variables, and a timed-out child gets SIGTERM followed by SIGKILL after a short grace period.
- The standalone index now has an optional generic Language Server Protocol symbol provider. A caller configures a local server command; the provider speaks bounded Content-Length framed JSON-RPC over stdio with shell execution disabled, timeouts, response-size caps and a child environment that also drops loader-hijack variables, requests document symbols only, rejects non-local root URIs, waits for in-flight work when closed, accepts both hierarchical and flat responses, carries class containers, rejects malformed names and ranges, returns `null` for unsupported extensions, and supports asynchronous providers in the index. The test fixture is local and does not download or launch a real language server.
- The standalone index now stores local embeddings and supports hybrid retrieval: a dependency-free `LocalHashEmbeddingProvider` turns identifier subwords into deterministic, normalized vectors, vectors are bounded and validated on load, cosine scoring is numerically scaled, index format v4 persists one vector per file, a persisted index is rejected when its embedding provider, dimensions or format differ, incremental reindex recomputes only the changed file's vector, and `searchHybrid()` combines lexical matches with cosine similarity so a natural-language query such as "where is auth middleware" returns the middleware file in the top three. The local provider requires a lexical anchor; vector-only retrieval is opt-in for model-backed providers, so hash collisions cannot invent unrelated hits (neural and hosted embeddings remain later work).
- The standalone index now has an optional tree-sitter (WASM) symbol provider: the `@vscode/tree-sitter-wasm` 0.3.1 (MIT) runtime and the JavaScript, TypeScript and TSX grammars are vendored with SHA-256 checksums, the provider extracts interfaces, types, enums, namespaces, classes, methods, constructors, getters and setters with class containers, functions and variables, the built-in lexical extractor remains the default and the fallback when the WASM runtime is unavailable, and the index records which symbol provider built it so an index built by another provider is rejected and rebuilt rather than silently mixed.
- The standalone index now records call sites and answers bounded structural questions for agents: callers, callees, transitive impact and the shortest call path, with per-answer node and byte caps, ambiguity reported as candidates instead of guessed edges, and no source text in any answer.
- The standalone index engine now has a multi-project registry: up to 32 validated project roots are indexed together, each gets a bounded per-directory watcher tree on Unix and reconciliation polling on Windows, registration installs watchers before a catch-up refresh, ignored trees are excluded before watches are installed, unreadable directories fall back to polling and atomically replaced files stay covered, registration pins the resolved root and its device/inode identity and revalidates it after initial indexing, every refresh enforces that identity around reads and re-hashes the candidate against the root before committing it, registry-owned indexes stay in memory and reject reindex calls, a failed refresh restores the previous snapshot, generated index-file events are excluded while source files in a custom index directory remain watched outside standard ignored directories, rename reconciliation refreshes once nested watches attach so files created during attachment are indexed, queues are bounded, unchanged files are reused, and concurrent edits to three fixture repositories stay isolated and current.
- Project foundation: locked governing docs, documentation suite, guardian sub-agents, governance and docs checks, Windows build preflight.
- The standalone Vibe Context Engine now builds leaf and condensed summary DAGs over lossless session records, protects a fresh tail, and exposes bounded `grep`, `describe`, and `expand` recall tools as module APIs (not yet surfaced in the IDE).
- The standalone Vibe Context Engine now persists scoped project and user memory with a pending-review queue, revision-bound decisions, approved-only recall, source-trust tagging, case-safe project isolation, and capacity recovery through log compaction (review panel UI not yet surfaced in the IDE).
- The standalone Vibe Context Engine now assembles model context within a caller-set token budget in the fixed system -> rules -> spec -> repo map -> summaries -> fresh-tail order, reports included, omitted and dropped content, never rewrites required system, rules or spec text, bounds untrusted payloads, rejects whitespace-only optional sections, marks untrusted content in-band, measures the fully joined prompt before reporting a fit, never lets a caller tokenizer count fall below the conservative UTF-8 byte upper bound so it can only tighten the budget, and exposes a per-section hash manifest for prefix-cache reuse (IDE integration not yet wired).
- The standalone Vibe Context Engine now has an optional AgentCore adapter that mirrors the lossless session transcript to `agentcore-memory` through a caller-supplied client. It hydrates missing remote records only while the local prefix is unchanged, so a concurrent local write fails closed instead of corrupting the transcript, matches repeated transcripts by content rather than object prototype or key order, appends only unmirrored records in bounded batches, closes the remote session, keeps the local store authoritative when the remote is absent or fails, rejects divergent or malformed remote sessions, preserves valid JSON keys such as an own `__proto__` verbatim, validates a payload snapshot with an exact byte budget before storing it, and returns hydrated results labelled `untrusted-session-content` (records are stored as ordinary session records, so store consumers must still treat session content as untrusted; live gateway wiring not yet included).
- The standalone per-project index now extracts TypeScript and JavaScript declarations without a parser dependency, builds a case-insensitive identifier index, persists it atomically under `.vibe/index`, skips symlinks and oversized files, and reindexes a single changed file without re-reading the rest of the project (graph and semantic retrieval remain later milestones).

### Changed

- Stable-build product identity defaults now use Vibecodium, including a distinct Windows application identity and artifact base name.
- `dev/build.sh` identity exports (`APP_NAME`, `BINARY_NAME`, `GH_REPO_PATH`, `ORG_NAME`) now respect pre-set environment values and default to the Vibecodium identity, so local builds stamp patch placeholders and name artifacts with Vibecodium branding instead of VSCodium's (CI parity is a separate M0 slice). `ASSETS_REPOSITORY` now defaults to the Vibecodium product repository.
- The shipped stable build's `updateUrl` and `downloadUrl`, and the Linux package metadata download, homepage, and screenshot links, now point at the Vibecodium update feed (`vibe/update-feed` on `vibe/main`) and the Vibecodium repository instead of VSCodium's. The local insider build (`-i`) now targets the branded `ynotfins/vibecodium-insiders` repository, matching CI, which does not exist yet. No feed data or release is published by this change.
- The stable appstream entry, desktop keywords, Windows tile name, Debian maintainer, and RPM vendor and packager now identify Vibecodium instead of upstream VSCodium or Microsoft. The Snap rewrite now targets `resources/linux/snap/snapcraft.yaml` instead of repeating the RPM spec rewrite; that path is not present in this repository (the Snap manifests are under `stores/snapcraft/`), so the Snap branding is unverified against a real vscode checkout.
