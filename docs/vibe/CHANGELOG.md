## [Unreleased]

### Added

- The standalone index now has a cross-project graph edge layer. `buildCrossProjectGraph(registry)` reads the current indexes of the registered projects plus bounded, contained reads of source, `package.json`, Dockerfile and compose files, and emits project, module, symbol, route, package, env, port, database-table, MCP-tool and container nodes with project-module, route-definition, import, package-dependency, env-use, exposes-port, database-table-use, mcp-tool, container-image and `http-route-caller` edges. Route-to-caller matching links a client symbol in one repository to a route definition in another for the C3 acceptance check, with GET/POST kept distinct, caller template URLs tagged `template`, templated route definitions normalized to `:param`, client receivers such as `httpClient` distinguished from server receivers such as `router`, comments and string-only calls ignored, and absolute origins, query strings and base-URL variables stripped. The graph stores only identifiers, project-relative file paths, normalized route patterns, environment-variable names, ports, table names, tool names and image names; source values, environment values and request URLs are not retained. Import edges keep only a resolved project-relative target or a package name, stripping query strings and dropping URL or colon-bearing specifiers. Nodes, edges, caller answers and the snapshot carry `sourceTrust: 'untrusted-repository-content'`. HTTP caller extraction is capped at 1,000 per file and 5,000 per graph, and route matching uses a method-keyed trie instead of scanning every caller against every route. Route indexing is also bounded to 64 segments per route and 200,000 trie nodes; HTTP caller candidates are capped at 20,000 per file and route ranges are merged so exclusion is a binary search; the import/export scan is length-bounded. The public `CrossProjectGraph` constructor validates a persisted snapshot field-by-field, rejecting unknown fields, duplicate ids and missing references, and forces `sourceTrust` on nodes and edges. Every trie node, including parameter nodes, counts against the 200,000-node budget; each read stops at 1 MB + 1 byte and re-checks the size; persisted node and edge ids are restricted to a safe identifier alphabet and edge ids are deduplicated; a saturated route-range table disables caller inference for that file rather than risking false matches. Every source read is project-relative, rejects traversal and absolute keys, follows no symlinks, revalidates device/inode and containment, and is bounded per file, per project and in total; malformed registries, index snapshots and route queries fail closed with `CrossProjectGraphError`. This is the standalone C3 layer only: the graph panel (C4), IDE binding, persisted graph tables and semantic/LSP edge extraction remain later work. `node --test tests/vibe/cross-project-graph.test.mjs` builds two fixture repositories and asserts the route-to-caller edge plus the other C3 families, client.get/client.post callers, template-route normalization, the no-source-values boundary, forged-index rejection and the HTTP caller caps.

- The standalone index can now persist its file embeddings to LanceDB through an optional, caller-injected `@lancedb/lancedb` 0.41.0 driver. `ProjectIndex` takes a `vectorStore`, mirrors changed files with merge-insert, deletes removed files, and exposes `searchVectors(query)`. The store validates the driver, local-only database uri (format and bidi characters rejected), table shape, record hashes, vectors, dimensions, file names and returned hits; it rejects duplicate ids and unreadable row, result and merge-insert builder accessors, bounds cosine distance, chunks large deletes, tags results `untrusted-repository-content`, and takes no dependency of its own, so nothing is downloaded or bundled and `node vibe/tools/verify.mjs` still runs on a bare Node install. `refresh({ full: true })` backfills a new store for an existing index; `load()` keeps using the store that was already populated. The index and the vector store are not one transaction: the index is verified before the store is synced and the store is synced before the index file is written, so a store failure rejects the refresh; a failure after the store sync can leave newer vectors until the next refresh reconciles them.
- The standalone index now has an optional ast-grep structural pattern provider. A caller supplies a trusted local `sg` executable (the ast-grep 0.51.3 CLI contract: `sg run --stdin --lang <lang> --pattern <pattern> --json=stream --color never`); the provider writes the source to stdin, never scans a directory or writes a rule file, runs with shell execution disabled, filters secret-named and loader-hijack environment variables, enforces a timeout plus source, output, match and meta-variable caps, converts ast-grep's zero-based positions to one-based, normalizes its PascalCase language values, and rejects malformed streams, wrong-language matches and prototype-polluting meta names. Exit code 1 is treated as "no matches". Nothing is downloaded or bundled, and `ProjectIndex` does not use this provider yet. Returned match and meta-variable text replaces control, format and bidi characters, the result is tagged `sourceTrust: 'untrusted-source-content'`, the child environment also drops URL, URI and DSN variables plus Node, Electron and Bash loader variables, and a timed-out child gets SIGTERM followed by SIGKILL after a short grace period.
- The standalone index now has an optional generic Language Server Protocol symbol provider. A caller configures a local server command; the provider speaks bounded Content-Length framed JSON-RPC over stdio with shell execution disabled, timeouts, response-size caps and a child environment that also drops loader-hijack variables, requests document symbols only, rejects non-local root URIs, waits for in-flight work when closed, accepts both hierarchical and flat responses, carries class containers, rejects malformed names and ranges, returns `null` for unsupported extensions, and supports asynchronous providers in the index. The test fixture is local and does not download or launch a real language server.
- The standalone index now stores local embeddings and supports hybrid retrieval: a dependency-free `LocalHashEmbeddingProvider` turns identifier subwords into deterministic, normalized vectors, vectors are bounded and validated on load, cosine scoring is numerically scaled, index format v4 persists one vector per file, a persisted index is rejected when its embedding provider, dimensions or format differ, incremental reindex recomputes only the changed file's vector, and `searchHybrid()` combines lexical matches with cosine similarity so a natural-language query such as "where is auth middleware" returns the middleware file in the top three. The local provider requires a lexical anchor; vector-only retrieval is opt-in for model-backed providers, so hash collisions cannot invent unrelated hits (neural and hosted embeddings remain later work).
- The standalone index now has an optional tree-sitter (WASM) symbol provider: the `@vscode/tree-sitter-wasm` 0.3.1 (MIT) runtime and the JavaScript, TypeScript and TSX grammars are vendored with SHA-256 checksums, the provider extracts interfaces, types, enums, namespaces, classes, methods, constructors, getters and setters with class containers, functions and variables, the built-in lexical extractor remains the default and the fallback when the WASM runtime is unavailable, and the index records which symbol provider built it so an index built by another provider is rejected and rebuilt rather than silently mixed.
- The standalone index now records call sites and answers bounded structural questions for agents: callers, callees, transitive impact and the shortest call path, with per-answer node and byte caps, ambiguity reported as candidates instead of guessed edges, and no source text in any answer.
- The standalone index engine now has a multi-project registry: up to 32 validated project roots are indexed together, each gets a bounded per-directory watcher tree on Unix and reconciliation polling on Windows, registration installs watchers before a catch-up refresh, ignored trees are excluded before watches are installed, unreadable directories fall back to polling and atomically replaced files stay covered, registration pins the resolved root and its device/inode identity and revalidates it after initial indexing, every refresh enforces that identity around reads and re-hashes the candidate against the root before committing it, registry-owned indexes stay in memory and reject reindex calls, a failed refresh restores the previous snapshot, generated index-file events are excluded while source files in a custom index directory remain watched outside standard ignored directories, rename reconciliation refreshes once nested watches attach so files created during attachment are indexed, queues are bounded, unchanged files are reused, and concurrent edits to three fixture repositories stay isolated and current.
- Project foundation: locked governing docs, documentation suite, guardian sub-agents, governance and docs checks, Windows build preflight.
- The standalone Vibe Context Engine now builds leaf and condensed summary DAGs over lossless session records, protects a fresh tail, and exposes bounded `grep`, `describe`, and `expand` recall tools as module APIs (not yet surfaced in the IDE).
- The standalone Vibe Context Engine now persists scoped project and user memory with a pending-review queue, revision-bound decisions, approved-only recall, source-trust tagging, case-safe project isolation, and capacity recovery through log compaction (review panel UI not yet surfaced in the IDE).
- The standalone Vibe Context Engine now assembles model context within a caller-set token budget in the fixed system -> rules -> spec -> repo map -> summaries -> fresh-tail order, reports included, omitted and dropped content, never rewrites required system, rules or spec text, bounds untrusted payloads, rejects whitespace-only optional sections, marks untrusted content in-band, measures the fully joined prompt before reporting a fit, never lets a caller tokenizer count fall below the conservative UTF-8 byte upper bound so it can only tighten the budget, and exposes a per-section hash manifest for prefix-cache reuse (IDE integration not yet wired).
- The standalone Vibe Context Engine now has an optional AgentCore adapter that mirrors the lossless session transcript to `agentcore-memory` through a caller-supplied client. It hydrates missing remote records only while the local prefix is unchanged, so a concurrent local write fails closed instead of corrupting the transcript, matches repeated transcripts by content rather than object prototype or key order, appends only unmirrored records in bounded batches, closes the remote session, keeps the local store authoritative when the remote is absent or fails, rejects divergent or malformed remote sessions, preserves valid JSON keys such as an own `__proto__` verbatim, validates a payload snapshot with an exact byte budget before storing it, and returns hydrated results labelled `untrusted-session-content` (records are stored as ordinary session records, so store consumers must still treat session content as untrusted; live gateway wiring not yet included).
- The standalone per-project index now extracts TypeScript and JavaScript declarations without a parser dependency, builds a case-insensitive identifier index, persists it atomically under `.vibe/index`, skips symlinks and oversized files, and reindexes a single changed file without re-reading the rest of the project (graph and semantic retrieval remain later milestones).

### Changed

- The shipped app, server, Linux, macOS, and Windows installer artwork now use the Vibecodium icon package; upstream icon downloads were replaced with local brand vectors and checked-in branded fallbacks.
- Stable-build product identity defaults now use Vibecodium, including a distinct Windows application identity and artifact base name.
- `dev/build.sh` identity exports (`APP_NAME`, `BINARY_NAME`, `GH_REPO_PATH`, `ORG_NAME`) now respect pre-set environment values and default to the Vibecodium identity, so local builds stamp patch placeholders and name artifacts with Vibecodium branding instead of VSCodium's (CI parity is a separate M0 slice). `ASSETS_REPOSITORY` now defaults to the Vibecodium product repository.
- The shipped stable build's `updateUrl` and `downloadUrl`, and the Linux package metadata download, homepage, and screenshot links, now point at the Vibecodium update feed (`vibe/update-feed` on `vibe/main`) and the Vibecodium repository instead of VSCodium's. The local insider build (`-i`) now targets the branded `ynotfins/vibecodium-insiders` repository, matching CI, which does not exist yet. No feed data or release is published by this change.
- The stable appstream entry, desktop keywords, Windows tile name, Debian maintainer, and RPM vendor and packager now identify Vibecodium instead of upstream VSCodium or Microsoft. The Snap rewrite now targets `resources/linux/snap/snapcraft.yaml` instead of repeating the RPM spec rewrite; that path is not present in this repository (the Snap manifests are under `stores/snapcraft/`), so the Snap branding is unverified against a real vscode checkout.
